- **官网标识改为命令行同款像素字标**（1920fa2，已推送）：用户要求「官网的全名标识换成命令行标识」。新增 `tools/gen-wordmark.mjs` —— 复用 `bin/orcode.js` 里同一套 5x5 GLYPHS 字形表生成 SVG，复刻命令行标识的视觉特征：**圆角像素块**（rx=3）**ORC 深灰 #5a6472 / ODE 浅灰 #b9c1cd 双色**（`half=ceil(len/2)` 决定分界）+ **底部立体暗带**（末行像素向下延伸 8px，用更深的 #3d444e/#8b939f，先画让主体覆盖上部形成厚度）+ **基线小圆点**（每字母下 3 个，r=2.6）。尺寸 700x125，导航栏缩到 132x24、Hero 缩到 420x75、README 顶部 420x75。
- ⚠️ SVG 生成时的**画布高度计算坑**：初版`totalH = 5*U + SH + 8` 没算圆点，导致圆点 cy 超出画布被裁。改为链式计算 `bodyH=5U → bandTop=bodyH → bandBottom=bandTop+SH → dotCY=bandBottom+DOT_GAP → totalH=ceil(dotCY+DOT_R+2)`，并**加断言验证「圆点底部 ≤ 画布高」「暗带紧贴主体底部」**，光栅化 PNG 肉眼复核后才部署。
- ⚠️ **Git Bash 与 Node 的 /tmp 路径不一致**：bash 的 `/tmp/x.html` 实际是 `C:\Users\...\AppData\Local\Temp`，但 Node 收到的是字面量 `/tmp` → 解析成 `D:\tmp`（因 cwd 在 D 盘）→ `ENOENT`。写临时文件用**项目内相对路径**（如 `./_x.html`）最稳，生成完立即删。
- 验证无浏览器时的实用手段：**手写 Node 脚本把 SVG 光栅化成 PNG**（解析 rect/circle →填像素 → zlib deflate → 手写 PNG chunk + CRC32），再用 Read 工具看图，能确认视觉效果是否符合预期。圆角用「四角圆心距离判定」近似即可。
- **背景盲文标志分辨率修复**（468ce84，已推送 + 全局包已重装）：用户反馈背景"散、看不清"。**根因 = 盲文点阵分辨率不足** —— 原 40 列 x 20 行（每点约 7.6px）无法表达螺旋星芒的细线条，细节大量丢失。实测各档高度：44列→22行 / 48列→24行 / 52列→26行 / 56列→28行 / 64列→32行。**最终选 48 列 x 24 行**（清晰度明显提升且能在 34 行终端完整显示，64 列会占满全屏）。新增可复用工具 `tools/png2braille.py`（用法 `python tools/png2braille.py <宽度> [阈值] [子采样]`，阈值 4/9 ≈ 覆盖率 44%）。
- ⚠️ **超长单行字符串常量改数组形式**：`const LOGO_ART = "…1854字符…"` 单行过长时，改成 `[ '行1', '行2', … ].join('\n')` 更稳妥（每行一个元素，便于 diff 与阅读）。
- ⚠️ **本轮踩坑：改`bin/orcode.js` 背景定位逻辑时，只要在背景渲染处引用 `logoN` 或 `foot` 这两个外层变量，4 个 smoke 测试就全部静默 exit=1（无任何输出，连 try/catch 都捕获不到，疑似沙箱层进程终止）**。排查过程：`node --check` 通过、变量作用域确认正确（665/681 行都在 831 行之前、同函数内）、文件无 CR/BOM/控制字符、换行符与 git HEAD 一致。最终**放弃改定位逻辑**（原 `top=(H-len)/2` 并非错误），改用「选更矮的点阵档位」从根上解决溢出问题（24 行能在 34 行终端容纳）。**教训：改动前先用最小复现验证（如 `void logoN;` 单行），确认再往下写，不要一次改多处。**
